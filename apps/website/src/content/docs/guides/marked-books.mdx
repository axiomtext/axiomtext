Teachers mark the important lines of a chapter; students read it with those marks, filter by
them, add their own highlights and tap a mark to practise the questions linked to it. Marks are
part of the document, so the same JSON works in the web editor, on your website and in Flutter.

## Mark types

Your app defines the kinds of marks. Each has an id, a label, a colour and a style: `fill`,
`underline`, `double` (double underline) or `box`. The id is what documents store, so keep it
stable; you can rename a type or change its colour at any time without touching saved content.

```js
import { createClassicEditor } from 'axiomtext';

const markTypes = [
  { id: 'IMPORTANT', label: 'গুরুত্বপূর্ণ', color: '#dc2626', style: 'fill' },
  { id: 'MARKED', label: 'দাগানো', color: '#2563eb', style: 'underline' },
  { id: 'PREVIOUS_YEAR', label: 'পূর্বের বছরের প্রশ্ন', color: '#ca8a04', style: 'box' },
];

const { editor } = createClassicEditor({ element, marks: { types: markTypes } });
```

Leave out `types` (`marks: {}`) to start with the defaults, `DEFAULT_MARK_TYPES`: Important (green
fill), Marked (blue underline) and Past exam question (amber box). Without a `marks` option there
is no Mark button.

Writers get a **Mark** menu (the marker-pen button) on the toolbar. Each type in the menu shows its
shortcut: <kbd>Alt</kbd>+<kbd>1</kbd>…<kbd>9</kbd> (<kbd>⌥</kbd>1… on a Mac) apply the types in
order and <kbd>Alt</kbd>+<kbd>0</kbd> removes the mark at the cursor. A mark is stored as
`{ type, id }` (plus optional data and badge) and survives copy and paste, undo and HTML.

| Command | What it does |
| --- | --- |
| `setMark(typeId, { id?, data?, badge? })` | Marks the selected text (replacing a mark there). |
| `removeMark(id?)` | Removes a mark everywhere, or the marks in the selection. |
| `setMarkData(id, data)` | Any JSON object kept with the mark, e.g. `{ questionIds: [...] }`. |
| `setMarkBadge(id, '3')` | A small badge after the mark, e.g. a question count. |
| `setMarkType(id, typeId)`, `selectMark(id)` | Change a mark's type; select and scroll to it. |

```js
editor.execute('setMark', 'pyq', { id: 'm42', data: { questionIds: ['q1', 'q2'] }, badge: 2 });

editor.getMarks();
// [{ id: 'm42', type: 'pyq', text: '…', page: 23, data: {…}, badge: '2', anchor: {…} }]
```

### Reading every mark

`editor.getMarks()` returns every mark in document order, in the [mark format](#the-mark-format)
below, so saving a chapter can turn each mark into a row:

```js
const marks = editor.getMarks();
await fetch('/api/chapters/12', {
  method: 'PUT',
  body: JSON.stringify({ document: editor.getJSON(), marks }),
});
```

The same list comes from `listMarks(json)` on saved JSON without an editor (in Node too),
`controller.getMarks()` in Flutter, and for PDFs from `annotator.getMarks()`,
`listPdfMarks(annotations)` or `controller.getPdfMarks()`: the selected text and its page, in
reading order. `editor.getPages()` lists the page blocks.

### Mark ids

A mark's id is how your app links things to it (questions, students' ticks), so it's kept stable
and unique:

| When the teacher… | The id |
| --- | --- |
| fixes a typo inside the mark, adds or deletes words in it | stays |
| undoes or redoes | stays (redo brings back the same ids) |
| re-marks the same text, changes its type, or extends it | stays, with its data and badge |
| presses Enter inside it | stays: one mark across two paragraphs |
| cuts it and pastes it somewhere else | stays |
| copies and pastes it (the original is still there) | the copy gets a new id, without data or badge |
| removes the mark from a middle part, leaving two halves | the first half keeps it; the second gets a new id, without data |
| marks across two marks | the first one's id (and data) wins; the second disappears |

Ids are letters, digits, `-` and `_`. Pass your own with `setMark(type, { id })`; otherwise
they look like `m3f9a2c41d07`.

### The mark format

This format is stable: fields may be added, but none will be renamed or removed. A server in any
language can read marks from it without running AxiomText.

**A mark**, as `getMarks()` returns it:

```json
{
  "id": "m3f9a2c41d07",
  "type": "PREVIOUS_YEAR",
  "text": "F = ma",
  "page": 24,
  "data": { "questionIds": ["q7"] },
  "badge": "2",
  "anchor": { "exact": "F = ma", "prefix": "second law: ", "suffix": " where F is" }
}
```

`page` is the number of the last page block before the mark (`null` without one); `data` and
`badge` are `null` when not set.

**In the saved JSON**, a mark is a `marker` entry in the `marks` of each text node it covers, and
a page is a `page` block:

```json
{ "type": "page", "attrs": { "number": 24 } }
{ "type": "text", "text": "F = ma",
  "marks": [{ "type": "marker",
              "attrs": { "type": "PREVIOUS_YEAR", "id": "m3f9a2c41d07",
                         "data": { "questionIds": ["q7"] }, "badge": "2" } }] }
```

To read marks yourself, walk the document depth first, remember the number of the last `page`
block, and collect text nodes by `marker` id: the first one gives the mark's type, data, badge and
page; join the texts of later ones, with a space between parts in different paragraphs. A mark
can cover several text nodes (when part of it is bold, say) and several paragraphs.

**In saved HTML**, a mark is
`<mark class="ax-mark" data-mark-id="…" data-mark-type="…" data-mark='{"questionIds":["q7"]}' data-badge="2">`
and a page is `<div class="ax-page" data-page="24">`.

### Choosing the buttons per screen

Every button is a toolbar item you can include or leave out: `mark` and `page` for marked books,
`comment` (**Add comment**) and `commentsPanel` (**All comments**) for comments. For example, a
teacher drafting a chapter gets marks without comments, a reviewer gets comments, and students
read with no toolbar at all (read-only editors show none unless you ask for one):

```js
// Teacher drafting
createClassicEditor({ element, marks: { types: markTypes },
  toolbar: ['undo', 'redo', '|', 'bold', 'italic', 'highlight', 'mark', '|', 'math', 'image'] });

// Reviewer
createClassicEditor({ element, comments: { author }, marks: { types: markTypes },
  toolbar: ['comment', 'commentsPanel'] });

// Student
createClassicEditor({ element, editable: false, marks: { types: markTypes } });
```

## Page numbers

A **page** block marks where a printed page starts, labelled in the reader's language and digits
("Page 23", "পৃষ্ঠা ২৩"). Insert one from **More → Page number** (it continues the numbering);
select it to change the number. The label isn't part of the text, so copying and searching ignore
it.

```js
editor.execute('insertPage', 23);
editor.execute('scrollToPage', 23);
listPages(editor.getJSON()); // [{ number: 23, index: 0 }, …]
```

Marks, reader highlights and selection actions report the `page` they're on.

## Reading: taps, legend and filters

On read-only content (a read-only editor, or [your website](/guides/website-rendering/) with
`axiomtext/viewer`) readers see a legend of the mark types with counts. Tapping a type shows or
hides it; **Only marked** folds every paragraph without a mark into "… 3 paragraphs", which
expands on tap.

```js
createClassicEditor({
  element,
  content: chapter,
  editable: false,
  marks: {
    types: markTypes,
    filter: 'all', // 'marked', or ['important', 'pyq']
    legend: true,
    onClick: ({ id, type, text, data, page, rect }) => showQuestions(data.questionIds, rect),
  },
  highlights: { items: myHighlights, onChange: saveHighlights }, // readers' own highlights
  selectionActions: [
    { id: 'ask', label: 'Ask AI' },
    { id: 'practise', label: 'Practise' },
  ],
  onSelectionAction: ({ actionId, text, anchor, page }) => run(actionId, text, page),
});
```

`onClick` gives you the mark's data and its position on screen, so you can show your own chip
("3 questions · Practise").

### Readers' own states

A student's progress on a mark (learned, needs review…) belongs to the student, not the
document. Set it on the reader's screen and choose how each state looks; the filter can use it:

```js
const { editor } = createClassicEditor({
  element,
  content: chapter,
  editable: false,
  marks: {
    types: markTypes,
    states: { learned: { fade: true, badge: '✓' } },
  },
});
editor.execute('setMarkStates', { m42: 'learned', m43: 'learned' }); // from your database
editor.execute('setMarkState', 'm44', 'learned'); // the student ticked one
editor.execute('setMarkState', 'm44', null); // and unticked it

// "Not learned yet": paragraphs with only learned marks fold away.
editor.execute('setMarkFilter', { excludeStates: ['learned'] });
```

A learned mark fades and gets a ✓ after its own badge. Marks with a state also get
`data-mark-state="learned"` for your own CSS (on the mark on web pages, on its text inside an
editor: style it with `mark.ax-mark:has([data-mark-state='learned'])`). States never change the
document. Filters can be `{ types, states, excludeStates }`: for example
`{ types: ['PREVIOUS_YEAR'], excludeStates: ['learned'] }`.

On a web page with `axiomtext/viewer`, use
`createViewer(root, { marks: { types, states, initialStates } })` with
`viewer.setMarkState(id, state)` and `viewer.setMarkFilter(filter)`. Selection actions add your buttons to the menu readers get when they
select text, with the same anchor (quote and context) as reader highlights.

## Flutter

```dart
AxiomTextEditor(
  readOnly: true,
  initialContent: AxiomContent.json(chapter),
  markTypes: const [
    AxiomMarkType(id: 'important', label: 'গুরুত্বপূর্ণ', color: Color(0xFF16A34A)),
    AxiomMarkType(id: 'pyq', label: 'পূর্বের বছরের প্রশ্ন', color: Color(0xFFB45309),
        style: AxiomMarkStyle.box),
  ],
  markFilter: AxiomMarkFilter.marked,
  markStateStyles: const {'learned': AxiomMarkStateStyle(fade: true, badge: '✓')},
  markStates: learnedByThisStudent, // {'m42': 'learned', …}
  onMarkTap: (mark) => showQuestions(mark.data?['questionIds']),
  selectionActions: const [AxiomSelectionAction(id: 'ask', label: 'Ask AI')],
  onSelectionAction: (event) => askAi(event.text),
);

// Per screen: the teacher drafts with marks, no comments.
AxiomTextEditor(
  markTypes: myMarkTypes, // or AxiomMarkType.defaults
  toolbarItems: const [
    AxiomToolbarItem.undo, AxiomToolbarItem.redo, AxiomToolbarItem.divider,
    AxiomToolbarItem.bold, AxiomToolbarItem.highlight, AxiomToolbarItem.mark,
    AxiomToolbarItem.page,
  ],
);

await controller.setMark('important', data: {'questionIds': ['q1']});
await controller.getMarks();       // List<AxiomMark>
await controller.scrollToPage(23);
await controller.setMarkState(mark.id, 'learned');
await controller.setMarkFilter(AxiomMarkFilter.query(excludeStates: ['learned']));
await controller.notebook();       // the reader's highlights in reading order, with pages
```

For long lists (quiz questions, answer options) use
[`AxiomTextView`](/frameworks/flutter/#native-view-no-webview): the same content drawn with Flutter
widgets, marks and equations included, without a WebView.
